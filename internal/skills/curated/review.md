# review

Review code changes before they land.

Prioritize, in order:
1. Bugs and behavioral regressions, with file/line references.
2. Security, permission, and data-loss risks.
3. Missing or broken tests for changed behavior.
4. Readability and consistency with existing patterns.

Present findings first, ordered by severity. Keep summaries brief and place them after the issues. If there are no issues, say so and note any remaining test gaps.
